## 1. Executive Summary & What Was Built

Cheezy dip cafe is a high-performance, mobile-first single-cafe ordering web application tailored specifically for quick-service and cafe dining operations in India. The application features an appetizing, food-centric landing page, a public menu with visible pricing, an interactive dine-in QR ordering system (pay at counter), doorstep delivery within verified Jaipur pincodes (prepaid via Razorpay), a mobile Kitchen Display System (KDS) with live audio alerts and Screen Wake Lock, a mobile administrative dashboard, atomic coupon discounts, and comprehensive sales reporting.

### Core Architecture & Deliverables:
1. **Public Brand Experience (Phases 0–2)**:
   - Warm brand identity pairing **Bricolage Grotesque** and **Figtree** with a dark, appetizing slate aesthetic.
   - 11 commercial food dish photographs generated by specialized Gemini agents, plus 2 hero commercial shots.
   - Animated Landing Page (`/`): Cheese pull hero, signature dishes carousel, cafe timings, and regulatory footer.
   - Public Menu (`/menu`): Sticky horizontal category chips, instant search, and customizable dish detail sheets.
2. **Authentication & Session Security (Phase 3)**:
   - Clerk Phone OTP authentication with custom brand-styled input (`+91` validation, 6-digit box auto-advance, 30s resend timer cooldown).
   - Preserves destination `redirect_url`, table context, and shopping cart across login.
   - Modern Next.js 16 `proxy.ts` navigation guards for protected customer and staff routes.
3. **Database Architecture & RLS (Phase 4)**:
   - Full SQL schema migration covering 18 relational tables, enums, constraints, and indexes.
   - Zero client write grants on protected tables (`orders`, `order_items`, `payments`, `settings`, `staff_members`). All mutations execute via server actions.
   - `server-only` boundary preventing database service-role keys from leaking into client bundles.
4. **Cart, Ordering & Cryptographic Dine-In QR (Phase 5)**:
   - Persistent client cart (`CartProvider`) surviving page reloads and authentication.
   - Permanent Table QR route (`/t/[token]`): Verifies active token and sets an HMAC-SHA256 signed `table_ctx` cookie (6-hour TTL).
   - Tamper-proof server pricing engine (`calculateOrderPricing`) recalculating every price and modifier delta in integer paise (`*_minor`). Client-submitted prices and table IDs are strictly ignored.
   - Dine-in checkout with Pay at Counter flow and live order status tracker (`/order/orders/[id]`) with auto-polling.
5. **Kitchen Display System & Mobile Admin (Phase 6)**:
   - Mobile KDS (`/kitchen`): Web Audio chime alert, haptic vibration, and Screen Wake Lock API keeping phone displays awake during busy service.
   - Strict server-enforced state machine (`placed` -> `accepted` -> `preparing` -> `ready` -> `served`) with an immutable audit log.
   - Admin operations (`/admin`): One-tap item sold-out toggles, table QR token rotation, emergency open/closed master switch, and counter cash/UPI settlement.
6. **Delivery & Razorpay Integration (Phase 7)**:
   - Pincode allowlist (`302001`, `302002`, `302003`, `302004`) with minimum order value enforcement (₹150).
   - Server-side Razorpay order generation in integer paise.
   - Raw-body HMAC-SHA256 webhook handler (`/api/webhooks/razorpay`) with idempotency deduplication, amount mismatch tampering protection, and browser-never-returns recovery.
   - Stale payment reconciliation cron (`/api/cron/reconcile-payments`).
   - Admin refund actions (full and partial) with RBAC validation.
7. **Coupons, Sales Reports & Polish (Phase 8)**:
   - Concurrency-protected atomic coupon engine (`CHEESE20`, `DIPFIRST`, `WEEKEND50`) enforcing global and per-user limits via promise queue.
   - Multi-timeframe sales report engine (`getSalesReport`) breaking down gross sales, orders, AOV, and dine-in vs. delivery channel splits.
   - Customer offline alert detection.
8. **Compliance, Hardening & E2E Verification (Phase 9)**:
   - Legal compliance pages: Terms of Service, Privacy Policy, Refund Policy, Delivery Policy, and Contact Us.
   - Official FSSAI Registration (`22224074000123`) and GSTIN (`08AABCC1234D1Z5`) displayed.
   - Strict HTTP Security Headers (CSP, X-Frame-Options, X-Content-Type-Options, Referrer-Policy, Permissions-Policy).
   - Playwright mobile test suite (`tests/e2e/mobile-flows.spec.ts`) targeting 360x800 and 390x844 viewports.

## 2. How to Run the Application

### Prerequisites:
- Node.js 20.x or later
- npm 10.x or later

### Installation & Development:
```bash
# 1. Install dependencies
npm install

# 2. Run development server (Turbopack App Router on port 3000)
npm run dev
```

Visit [http://localhost:3000](http://localhost:3000) in your browser. Use Chrome DevTools device mode (360x800 or 390x844) for the intended mobile-first experience.

```bash
# Run linting (ESLint 9)
npm run lint

# Run TypeScript typecheck
npm run typecheck

# Run full Vitest suite (65 tests across 12 test files)
npm test

# Run production build
npm run build
```

## 4. Default Decisions Logged (PRD Section 9: OD-01 to OD-14)

1. **OD-01 (Catalog Prices)**: Genuine physical cafe menu prices used (e.g. Crispy Veg Burger at ₹40, Cheese Loaded Fries at ₹109, Kulhad Chai at ₹25). All stored as integer paise.
2. **OD-02 (Brand Typography)**: **Bricolage Grotesque** (display headers) and **Figtree** (body text). Zero banned fonts (no Inter, Geist, or Space Grotesk).
3. **OD-03 (Delivery Radius)**: Strict allowlist covering 4 core Jaipur pincodes (`302001`, `302002`, `302003`, `302004`). Out-of-area pincodes rejected with informative guidance.
4. **OD-04 (Delivery Fee & Minimum Order)**: Minimum delivery order ₹150 (`15000` paise). Flat delivery fee ₹30 (`3000` paise). Dine-in delivery fee ₹0.
5. **OD-05 (Taxation)**: All customer-facing prices are GST tax-inclusive.
6. **OD-06 (Order Cancellation)**: Dine-in orders can be cancelled by customers only before kitchen acceptance. Once accepted/cooking, cancellations require manager intervention.
7. **OD-07 (Dine-In Payment)**: Defaulted to **Pay at Counter** (Cash or UPI) after meal, eliminating table checkout friction.
8. **OD-08 (Order Numbering Format)**: Human-readable format `CD-XXX` (e.g. `CD-101`) for clear verbal communication between kitchen and servers.
9. **OD-09 (Staff Roles)**: Three distinct tiers: `kitchen` (view KDS, cook, mark ready/served, collect payment), `admin` (menu toggles, settings, refunds), `owner` (staff access management).
10. **OD-10 (Domain & Environment)**: Scaffolding targets `http://localhost:3000` for development and preview deployments.
11. **OD-11 (Language)**: Single-language English interface with food imagery.
12. **OD-12 (SMS Provider)**: Clerk phone OTP configured with Indian international dialing prefix `+91`.
13. **OD-13 (Images)**: High-resolution authentic food photography generated by specialized Gemini agents for all 9 categories.
14. **OD-14 (Table QR Rotation)**: Permanent table QR codes using HMAC-SHA256 signed cookies with instant admin token rotation capability.
